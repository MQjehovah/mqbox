# 快速笔记插件 — 点击面板笔记打开详情页

## 需求概述

在快速笔记插件（quick-notes）的面板（Panel）中，点击任意笔记条目，在当前面板内展开详情视图，支持查看完整内容、编辑内容和删除笔记。解决"面板看得到笔记摘要却无法查看完整内容"的路径断层问题。

## 用户故事

1. 作为**快速笔记用户**，我在按 `Alt+Space` 呼出面板后，看到最近笔记的摘要，我想点击某条笔记查看**完整内容**，而不是跳转到列表页再手动查找。
2. 作为**快速笔记用户**，在详情视图中我发现笔记内容有错别字或需要补充，我想**直接编辑**并保存，不用切换到列表页再重新找到它编辑。
3. 作为**快速笔记用户**，在详情视图中我发现这条笔记已经没用了，我想**直接删除**。
4. 作为**快速笔记用户**，查看完详情后，我想通过**点击空白处或按 ESC** 关闭详情视图，回到面板概览。

## 功能优先级表

| 优先级 | 功能 | 说明 |
|--------|------|------|
| **P0** | 点击面板笔记条目 → 展开详情视图 | 点击任意笔记卡片，面板内容切换为展示该笔记的完整内容 |
| **P0** | 详情视图展示完整 content 和时间 | 不再截断 50 字，展示全部文本内容 |
| **P0** | 详情视图中展示 tags | 以标签样式展示笔记所有标签 |
| **P0** | 关闭详情视图回到面板概览 | 点击遮罩层/返回按钮/ESC 键，回到笔记列表概览 |
| **P1** | 详情视图中编辑 content | 点击"编辑"进入可编辑模式，修改后保存 |
| **P1** | 详情视图中删除笔记 | 点击"删除"按钮，确认后删除该笔记并返回概览 |
| **P2** | 编辑时管理 tags（增删标签） | 在编辑模式下支持修改标签 |
| **P2** | 动画过渡效果 | 面板内视图切换时的平滑动画 |

## 质疑检查清单回答

### Q1: 用户真正的痛点是什么？（不是他们要求的功能）

**真正的痛点不是"需要详情页"，而是"信息获取的路径断层"。**

用户在面板中已经看到了笔记摘要（50字截断），知道"有这条笔记"，但当想查看完整内容时，只能点击"openPage"跳转到 Page 列表页，然后在众多笔记中重新搜索/滚动定位到目标笔记。这个过程在笔记数超过 5 条时就开始让人烦躁。用户真正想要的是**零跳转的信息获取**——看到摘要 → 点进去看全文 → 回到概览，整个流程在面板内闭环，不离开当前上下文。

### Q2: 不做这个会怎样？有没有更简单的替代方案？

**不做的话，用户只能走现有路径：**
1. 点击面板的 `→` 按钮跳转到 Page 列表页
2. 在列表页中手动查找那条笔记（按时间排序，需要视觉扫描）
3. 阅读完后再关闭页面回到主搜索框

**替代方案评估：**
- 方案 A：在面板中把摘要从 50 字延长到全文显示 → 不可行，面板空间有限，多条笔记会撑爆布局
- 方案 B：hover 时 tooltip 显示全文 → 可以作为一种轻量方案，但不支持编辑和交互
- **结论：详情视图是最合理方案，没有更简单的等效替代**

### Q3: 这个功能的成功标准是什么？如何衡量？

| 标准 | 衡量方式 |
|------|----------|
| 点击笔记 → 看到完整内容 ≤ 500ms | 无额外网络请求，本地状态切换即可 |
| 用户无需离开面板即可完成"查看全文" | 从点击到返回概览全程在面板内 |
| 编辑/删除操作成功率 100% | 调用已有 `execute('delete')` 和新增 `execute('update')` |
| 用户不再需要通过 Page 列表页来查看笔记详情 | 可通过减少 Page 页的访问次数来追踪 |

### Q4: 技术上最大的风险点在哪？

**风险很低，主要是状态管理的一致性。**

1. Panel 当前是纯展示组件，没有"详情视图"的状态——需要新增 `selectedNote` 响应式状态来控制视图切换
2. 编辑功能需要新增 `execute('update', { id, content, tags })` 命令，但增删查的基础设施已经完备
3. 编辑中如果用户在外部删除了这条笔记（理论上在面板内不会发生），保存时会找不到记录——需要做好态检查

**风险评估：低。** 这是纯 UI 层的功能扩展，不涉及数据层重构。

### Q5: 如果要 1 天内交付，会砍掉什么？

**P1 和 P2 全砍，只做 P0：**

- 仅支持**查看完整内容**（只读模式），不做编辑和删除
- 详情视图只展示 content + tags + time，不可交互
- 通过点击遮罩层/ESC 返回概览
- 没有动画过渡

这样 1 天内可交付版本：新增一个 `showDetail(note)` 状态 + 一块条件渲染的详情区域即可。

### Q6: 有没有竞品已经做过？我们比他们好在哪里？

**竞品现状：**
- **Notion Quick Notes**：点击笔记卡片会展开内联详情，支持编辑，交互流畅
- **Obsidian Quick Add 插件**：搜索结果中点击笔记直接打开编辑器
- **Raycast Notes**：点击笔记条目直接在当前窗口展示完整内容

**我们的优势：**
- 更轻量：不跳转新窗口/新标签页，面板内展开后即时可返回
- 更聚焦：只做"查看 → 编辑 → 删除"三件事，不做复杂排版
- 一致性：与 MQBox 自身的面板交互范式一致（搜索、操作、返回）

## 范围边界

### 做（In Scope）
- ✅ 面板内点击笔记条目展开详情视图
- ✅ 详情视图显示完整 content、tags、time
- ✅ 支持编辑 content 并保存
- ✅ 支持删除笔记（带确认）
- ✅ ESC / 点击遮罩 / 返回按钮关闭详情
- ✅ 新增 `execute('update')` 命令支持编辑保存
- ✅ 编辑/删除后刷新面板概览的数据

### 不做（Out of Scope）
- ❌ 不做独立的新页面/新路由（详情在面板内展开）
- ❌ 不做标签管理（增删标签推迟到 P2）
- ❌ 不做富文本编辑（纯文本编辑即可）
- ❌ 不做笔记分享/导出
- ❌ 不做历史版本/撤销
- ❌ 不改动 Page.vue（列表页不受影响）

## 验收标准（Acceptance Criteria）

### AC1: 点击笔记展开详情
- 给定面板展示最近笔记列表
- 当用户点击任意一条笔记卡片
- 面板内容切换为详情视图
- 展示该笔记的完整 content（不截断）
- 展示所有 tags（以标签样式）
- 展示格式化的 time

### AC2: 关闭详情返回概览
- 给定详情视图已打开
- 当用户点击左上角"← 返回"按钮
- 或按下 ESC 键
- 或点击详情区域外的遮罩层
- 面板回到笔记列表概览视图

### AC3: 编辑笔记
- 给定详情视图已打开
- 当用户点击"编辑"按钮
- content 区域变为可编辑状态（textarea）
- 用户修改内容后点击"保存"
- 调用 `execute('update', { id, content })` 保存
- 详情视图更新为新内容
- 面板概览中的摘要同步更新

### AC4: 删除笔记
- 给定详情视图已打开
- 当用户点击"删除"按钮
- 弹出确认提示"确定删除这条笔记吗？"
- 用户确认后调用 `execute('delete', { id })`
- 自动返回面板概览
- 该笔记不再出现在列表中
- 面板笔记计数同步更新

### AC5: 边界情况
- 笔记内容为空时，详情视图显示"（空笔记）"占位符
- 笔记 tags 为空时，不显示标签区域
- 编辑时 content 为空，点击保存应提示"内容不能为空"并阻止保存
- 连续快速点击多条笔记 → 每次切换正常，无卡顿或数据错乱

## 数据流说明

```
用户点击笔记卡片
  → Panel: selectedNote = note (响应式状态)
  → 视图切换: 列表模式 → 详情模式
  → 展示完整 content / tags / time

用户编辑并保存
  → Panel: 调用 props.execute('update', { id, content })
  → index.ts: 注册的 'update' 命令更新 notes 数组
  → storage.set('notes', notes) 持久化
  → Panel: selectedNote.content 同步更新

用户删除
  → Panel: 确认后调用 props.execute('delete', { id })
  → index.ts: 注册的 'delete' 命令删除 + 持久化
  → Panel: selectedNote = null, 返回列表概览
```
